## 0. PRD 摘要（中转用）

- **产品目标**：将 claude_trading 已有的采集、链上、评分、回测等分析能力聚合为一个**可交互的 Web 投研控制台**，替代当前静态 ECharts 看板，支持指标展示、叙事/新闻、竞品对比、投资建议与百倍币机会捕捉。
- **面板清单（6 个）**：① 市场总览 ② 币种档案 ③ 竞品对比 ④ 链上分析 ⑤ 评分与建议 ⑥ 百倍币机会雷达；外加顶部导航 + 深色科技风视觉规范。
- **P0 需求数**：5 条（后端 API 骨架、前端框架搭建、市场总览、币种档案、百倍币雷达）。
- **V1 集成模式**：四个现有分析项目作为数据面板直接复用，不重写核心算法。

## 1. 产品目标

claude_trading 投研控制台是一个面向加密货币研究者与量化爱好者的**全栈 Web 应用**，用于把平台既有的每日数据采集、代币/DeFi 研究、链上 8 维评分、投资建议与回测等离散能力，统一为一个**可交互、可导航的投研控制台**。它不再只是 `build_dashboard.py` 生成的静态 HTML，而是：实时读取本地 `daily_scan` 与 `raw_server` 数据并调用 `src/` 分析模块，提供市场总览、币种档案（含离线叙事/新闻信号与可选实时抓取）、竞品对比、链上体检、评分与宏观闸门、以及全新的「百倍币机会雷达」；帮助用户在海量币种中快速定位叙事热度、成长性与链上健康度兼备的潜在高倍机会，降低投研信息整合成本。

## 3. 需求池

优先级定义：**P0 = 必须有（MVP 上线门槛）**；**P1 = 应有（V1 内完成）**；**P2 = 可有（后续迭代）**。

### 3.1 P0（必须有）

#### REQ-P0-01 后端 API 骨架（FastAPI）
- **描述**：搭建 FastAPI 应用，统一封装本地数据读取（`data/reports/daily_scan/<date>/`、`data/raw_server/<source>/<date>.parquet`）与 `src/` 分析模块导入（`token_defi`、`web_research`、`chain`、`scorer`、`advice`、`comparison`、`btc_dominance`、回测）。提供标准化 JSON 接口与 CORS。
- **验收标准**：
  - 启动 `uvicorn` 可访问 `/docs`（OpenAPI 自动文档）。
  - 提供至少以下端点且返回结构化 JSON：`/api/market/overview`、`/api/tokens`、`/api/tokens/{id}`、`/api/opportunity/radar`、`/api/comparison`、`/api/onchain/{id}`、`/api/score/{id}`、`/api/macro/btc-dominance`。
  - 读取 `daily_scan` 失败时返回明确错误码与空态结构，不崩溃。
  - 允许通过 `?date=` 指定数据日期，缺省取最新日期目录。

#### REQ-P0-02 前端框架搭建（Vite + React + MUI + Tailwind，深色主题）
- **描述**：初始化 Vite + React 工程，集成 MUI 与 Tailwind CSS，落地深色科技风主题（蓝/青/紫渐变），搭建布局骨架（顶部导航 + 内容区 + 路由）。
- **验收标准**：
  - 工程可 `npm run dev` 启动并访问。
  - 顶部导航可切换 6 个面板路由，无白屏报错。
  - 全局深色主题生效（背景近黑、卡片半透明玻璃质感、主色为蓝/青/紫渐变），与 MUI + Tailwind 共存无样式冲突。
  - 已封装基础 API 请求层（fetch/axios）指向 FastAPI 地址。

#### REQ-P0-03 市场总览面板
- **描述**：展示当日市场 KPI 与概览：总市值、24h 成交量、BTC 主导率、上涨/下跌币种数、板块热力、Top 代币快照（来自 `summary.json` + `top_800_light`）。
- **验收标准**：
  - 渲染 `summary.json` 关键 KPI 与图表（市值趋势/涨跌分布/板块分布）。
  - 提供 Top 代币列表（可点击进入币种档案）。
  - 数据加载失败显示空态/错误提示，不阻塞导航。

#### REQ-P0-04 币种档案面板
- **描述**：单币详情页，聚合 `top_50_detailed`/`by_category` 深度数据 + 离线叙事/新闻信号（Reddit 提及、社区分、新闻计数、情绪）作基线展示；提供「实时抓取」按钮，网络可达时触发 `web_research` 补充叙事/新闻（异步、不阻塞首屏）。
- **验收标准**：
  - 首屏以离线信号渲染叙事简介、赛道标签、社区情绪、官方链接、新闻计数。
  - 「实时抓取」按钮可触发后端 `web_research` 调用，过程中显示 loading，失败有兜底提示并保留离线内容。
  - 关联展示该币的评分/建议/链上入口（链接跳转或内嵌摘要）。

#### REQ-P0-05 百倍币机会雷达面板
- **描述**：机会扫描器——基于小市值 + 成长/叙事/社区/链上信号，以排行榜 + 雷达图呈现潜在高倍机会（启发式打分细节由架构师/工程师设计，PRD 仅定义目标与维度）。
- **验收标准**：
  - 提供机会排行榜（可按维度排序、筛选市值区间）。
  - 单条机会展示多维度雷达图（含市值规模、成长性、叙事热度、社区强度、链上健康等维度）。
  - 维度定义与数据来源清晰可追溯（映射到现有信号/模块）。
  - 点击机会可跳转币种档案。

### 3.2 P1（应有，V1 内）

#### REQ-P1-01 竞品对比面板（token_defi）
- **描述**：选择 2-3 个代币，对比代币经济与估值（流通率/稀释/解锁抛压、FDV/MC、P/S、协议横向对比、资本效率）。
- **验收标准**：
  - 多选代币后并排展示关键指标对比表/图。
  - 数据来源于 `src/research/token_defi.py`，口径与现有分析一致。
  - 支持从市场总览/币种档案一键加入对比。

#### REQ-P1-02 链上分析面板（src/chain）
- **描述**：展示代币在 BNB/SOL/Robinhood 的 8 维评分（安全/趋势/动量/流动性/情绪/创新/分类/社区）与链上体检结论。
- **验收标准**：
  - 渲染 8 维评分雷达/条形与体检摘要。
  - 数据来源于 `src/chain/`，币种不存在该链数据时显示「无数据」。

#### REQ-P1-03 评分 / 建议 / 宏观面板
- **描述**：聚合 `scorer`+`advice` 综合评分与投资建议、`btc_dominance` 宏观闸门、`backtest_simple` 回测摘要。
- **验收标准**：
  - 展示单币综合评分、建议等级、触发理由。
  - 展示 BTC 主导率宏观闸门状态（如「适合/谨慎」）。
  - 提供回测摘要视图（策略名、收益/回撤等关键指标）。

### 3.3 P2（可有，后续迭代）

#### REQ-P2-01 实时 web_research 触发（全局）
- **描述**：在更多入口（如市场总览批量、雷达机会）支持一键触发实时 `web_research`，统一限流与缓存。
- **验收标准**：全局触发有频率限制与超时兜底；结果可缓存至本地避免重复请求。

#### REQ-P2-02 数据日期切换
- **描述**：全局日期选择器，切换 `daily_scan` 不同日期回看历史。
- **验收标准**：切换日期后所有面板同步刷新；缺日期显示空态。

#### REQ-P2-03 导出
- **描述**：支持看板/对比/排行榜导出 CSV 或 PDF。
- **验收标准**：导出文件字段与当前视图一致。

#### REQ-P2-04 告警订阅
- **描述**：对关注的币或雷达机会阈值设置告警（邮件/Webhook/本地通知）。
- **验收标准**：达到阈值触发通知；订阅列表可增删改。

## 4. UI 设计稿

### 4.1 视觉规范（深色科技风）
- **背景**：近黑深蓝渐变（`#0a0e1a` → `#0d1424`），内容区辅以径向光晕。
- **主色**：蓝 `#3b82f6` / 青 `#22d3ee` / 紫 `#8b5cf6` 渐变；强调色用于高亮与 CTA。
- **卡片**：半透明玻璃质感（`rgba(255,255,255,0.04)` + 细描边 + 模糊），圆角 12-16px。
- **图表**：ECharts/Recharts 统一暗色配色，渐变填充。
- **字体**：无衬线，数字用等宽以对齐 KPI。
- **交互**：悬停微光、加载骨架屏、统一空态/错误态。

### 4.2 整体布局（Mermaid）

```mermaid
graph TD
    A[顶部导航栏<br/>Logo + 6 面板 Tab + 全局搜索/日期(可选)] --> B[内容区 Router]
```

## 5. 待确认问题（Open Questions）

1. **百倍币雷达打分权重**：各维度（市值规模、成长性、叙事热度、社区强度、链上健康）的权重与归一化方法如何确定？是否需用户可调？需与架构师/工程师共同设计启发式。
2. **鉴权需求**：控制台是纯本地单人使用，还是需要用户登录/多租户/权限隔离？影响后端会话与数据隔离设计。
3. **部署方式**：本地 `uvicorn`+`npm run dev` 即可，还是需要 Docker 化、云端部署、反向代理与 HTTPS？影响工程脚手架与配置。
4. **数据时效与刷新策略**：前端是固定读取最新 `daily_scan` 日期，还是轮询检测新日期主动提示？实时 `web_research` 的调用频率限制、超时与失败兜底策略如何设定（避免阻塞详情页）？
5. **P2 范围排序**：导出、告警订阅、日期切换中，哪些对 V1 用户价值最高、是否需提前纳入 P1？
